# GreenWatch AI — Production Deployment Guide

A step-by-step deployment guide for deploying **GreenWatch AI** to **Render** (free tier Web Service for `/server` and free tier Static Site for the React/Vite frontend) with **Supabase** (PostgreSQL + private evidence bucket).

---

## Prerequisites
- A GitHub account with a personal repository for this project.
- A free [Render](https://render.com) account.
- A free [Supabase](https://supabase.com) project.

---

## Step 1: Push Code to GitHub (a)
From your terminal in the project root:
```bash
git add .
git commit -m "chore: prepare production deployment blueprint"
git branch -M main
git remote add origin https://github.com/<YOUR_GITHUB_USERNAME>/<YOUR_REPOSITORY_NAME>.git
git push -u origin main
```

---

## Step 2: Create Render Blueprint (b)
1. Go to your [Render Dashboard](https://dashboard.render.com).
2. Click **New +** (top right) and select **Blueprint**.
3. Connect your GitHub account (if not already connected) and select your repository.
4. Render will parse `render.yaml` and discover two services:
   - `greenwatch-api` (Web Service, Node runtime, rootDir: `server`)
   - `greenwatch-web` (Static Site, build: `npm install && npm run build`, publish: `dist`)

---

## Step 3: Configure Environment Variables in Render (c)
Render will prompt you for variables marked `sync: false`. Here is where to find and set each value:

### 1. `greenwatch-api` (Backend Web Service)
| Variable | Value / Where to find it in Supabase | Notes |
|---|---|---|
| `NODE_ENV` | `production` | Preconfigured |
| `FRONTEND_URL` | Temporary placeholder: `https://localhost:5173` *(updated in Step 4)* | Allowed CORS origin |
| `COOKIE_SECRET` | Auto-generated by Render or random 32-character string | Cookie signing |
| `DATABASE_URL` | Supabase > Project Settings > Database > **Connection string** (URI / Transaction pooler) | e.g. `postgresql://postgres.[ref]:[password]@aws-0-[region].pooler.supabase.com:6543/postgres` |
| `SUPABASE_URL` | Supabase > Project Settings > API > **Project URL** | e.g. `https://[your-project-id].supabase.co` |
| `SUPABASE_ANON_KEY` | Supabase > Project Settings > API > Project API keys > **anon public** | Safe public key |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase > Project Settings > API > Project API keys > **service_role** *(secret)* | Bypasses RLS for storage / admin ops |
| `SUPABASE_STORAGE_BUCKET` | `evidence` | Evidence photo bucket |
| `STORAGE_DRIVER` | `supabase` | Uses Supabase Storage |
| `JWT_SECRET` | Auto-generated by Render or random 32-character string | JWT token signing |
| `JWT_EXPIRES_IN` | `7d` | Token expiry |
| `ADMIN_EMAIL` | `admin@greenwatch.gov` | Official login email |
| `ADMIN_PASSWORD` | Choose a strong password (e.g. `SuperSecretAdmin2026!`) | Official login password |
| `CRON_SECRET` | Choose a secret string (e.g. `cron_secret_gw_prod_99`) | Protects `/api/jobs/run` |
| `GEMINI_API_KEY` | Optional: [Google AI Studio](https://aistudio.google.com/) API Key | Falls back to civic heuristics if omitted |
| `GEMINI_MODEL` | `gemini-1.5-flash` | Multimodal model |

### 2. `greenwatch-web` (Frontend Static Site)
| Variable | Value | Notes |
|---|---|---|
| `VITE_API_URL` | Temporary placeholder: `https://placeholder-api.onrender.com` *(updated in Step 4)* | Backend base URL |

Click **Apply** to start building both services.

---

## Step 4: Link Real Render Domains & Redeploy (d)
Once Render provisions the services, you will get real `.onrender.com` URLs:
- Backend: e.g. `https://greenwatch-api-xxxx.onrender.com`
- Frontend: e.g. `https://greenwatch-web-yyyy.onrender.com`

1. Go to **greenwatch-web** > **Environment**:
   - Set `VITE_API_URL` to `https://greenwatch-api-xxxx.onrender.com`
   - Click **Save Changes** and click **Manual Deploy > Deploy latest commit**.
2. Go to **greenwatch-api** > **Environment**:
   - Set `FRONTEND_URL` to `https://greenwatch-web-yyyy.onrender.com`
   - Click **Save Changes** (Render will automatically redeploy the backend).

---

## Step 5: Run Database Schema & Seed (e)

### 1. Database Schema
Ensure `supabase_schema.sql` has been run against your Supabase project:
- In Supabase Dashboard, open **SQL Editor**.
- Copy all contents of `supabase_schema.sql` from this repo, paste, and click **Run**.
- Ensure the `evidence` bucket exists under **Storage** in Supabase and is set to **Private**.

### 2. Idempotent Seed
Run the seed once to populate baseline test reports and officials:
- **Option A (Render Shell)**:
  In Render Dashboard, open **greenwatch-api** > **Shell**, and run:
  ```bash
  npm run seed
  ```
- **Option B (Local with production DATABASE_URL / Supabase credentials)**:
  In your local terminal:
  ```bash
  cd server
  SUPABASE_URL="https://[ref].supabase.co" SUPABASE_SERVICE_ROLE_KEY="[key]" npm run seed
  ```

---

## Step 6: Configure GitHub Actions Keepalive (f)
Render's free tier spins down web services after 15 minutes of inactivity. The repository includes `.github/workflows/keepalive.yml` which pings `/api/health` and runs `/api/jobs/run` every 15 minutes.

1. In your GitHub repository, go to **Settings** > **Secrets and variables** > **Actions**.
2. Click **New repository secret**:
   - `BACKEND_URL`: `https://greenwatch-api-xxxx.onrender.com`
   - `CRON_SECRET`: Your `CRON_SECRET` string configured in Step 3.
3. Go to the **Actions** tab in GitHub, select **GreenWatch Keepalive & Cron**, and click **Run workflow** to verify.

---

## Step 7: Post-Deploy Verification Checklist (g)
Verify the live application in your browser:
- [ ] **Home & Report Submission**: Submit a new report with an attached photo (JPG/PNG). Confirm it navigates to the tracker or success screen with a reference ID (e.g. `GW-XXXX`).
- [ ] **Track Report**: Open `/track`, search your reference ID. Confirm status timeline, location, description, and the evidence photo appear. Confirm no confidential notes or email addresses leak.
- [ ] **Admin Login**: Click "Official Sign In" on the navbar, enter `admin@greenwatch.gov` and your `ADMIN_PASSWORD`. Confirm you are signed in and the "Official" badge appears.
- [ ] **Dashboard Refresh**: Navigate to `/dashboard` as official, view reports list with thumbnails, and refresh the browser (`F5`). Confirm the page does not 404.
- [ ] **Report Details & Resolution**: Open a report, change status from `New` -> `Assigned` -> `In Progress` -> `Resolved`.
- [ ] **Console Cleanliness**: Open browser DevTools (F12) > Console. Verify zero uncaught errors or CORS blocks.

---

## Step 8: Demo Day Notice (h)
> **Demo Day Note**: Because Render free tier services sleep when idle, cold starts can take 30–50 seconds on the first request. The frontend has silent retry backoff built in, but for an instant experience, **open your site 10 minutes before your presentation** or trigger the GitHub Action keepalive workflow so the container is already warm and responsive.
